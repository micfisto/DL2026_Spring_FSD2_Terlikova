# 1.1. Пользовательские сценарии 
## US-01. Запуск викторины и выбор режима

**Описание:**  
**Как пользователь**, я хочу запустить викторину и выбрать режим.

**Предусловия:**
- Пользователь открыл веб-приложение.
- Главная страница успешно загружена.

**Основной сценарий:**
1. Пользователь открывает приложение.
2. Система отображает стартовый экран.
3. Пользователь выбирает режим игры.
4. Пользователь нажимает кнопку **«Начать игру»**.
5. Система загружает первый вопрос.
6. Пользователь переходит на экран викторины.

**Постусловия:**
- Игровая сессия создана.
- Пользователь находится на первом вопросе викторины.

## US-02. Выбор ответа на карте

**Описание:**  
**Как пользователь**, я хочу отметить место на карте, чтобы ответить на вопрос.

**Предусловия:**
- Игра запущена.
- Текущий вопрос загружен.
- Карта отображается корректно.

**Основной сценарий:**
1. Система отображает текст вопроса.
2. Пользователь изучает карту.
3. Пользователь кликает по предполагаемому месту на карте.
4. Система отображает маркер в выбранной точке.
5. Пользователь подтверждает свой выбор.
6. Система сохраняет координаты ответа.

**Альтернативный сценарий:**
- Если пользователь хочет изменить ответ до подтверждения:
    1. Пользователь повторно кликает по другой точке карты.
    2. Система перемещает маркер на новое место.
    3. Пользователь подтверждает обновлённый выбор.

**Постусловия:**
- Координаты ответа пользователя зафиксированы.
- Система готова вычислить результат.
## US-03. Просмотр результата ответа

**Описание:**  
**Как пользователь**, я хочу получить результат ответа, чтобы понять, насколько точно я отметил местоположение объекта.

**Предусловия:**
- Пользователь выбрал точку на карте.
- Ответ подтверждён.

**Основной сценарий:**
1. Система принимает координаты ответа пользователя.
2. Система определяет правильные координаты объекта.
3. Система вычисляет расстояние между ответом пользователя и правильной точкой.
4. Система рассчитывает количество баллов за ответ.
5. Система отображает:
    - выбранную пользователем точку;
    - правильную точку;
    - расстояние ошибки;
    - количество начисленных баллов.
6. Общий счёт пользователя обновляется.

**Альтернативный сценарий:**
- Если пользователь не выбрал точку:
    1. Система не позволяет завершить ответ.
    2. Система отображает сообщение с просьбой выбрать точку на карте.

**Постусловия:**
- Ответ пользователя оценён.
- Баллы начислены.
- Результат текущего вопроса отображён.

## US-04. Переход к следующему вопросу

**Описание:**  
**Как пользователь**, я хочу быстро переходить к следующему вопросу.

**Предусловия:**
- Результат текущего вопроса уже показан.

**Основной сценарий:**
1. Пользователь нажимает кнопку **«Следующий вопрос»**.
2. Система отправляет запрос на получение нового вопроса.
3. Новый вопрос подгружается без перезагрузки страницы.
4. Система обновляет:
    - текст вопроса;
    - состояние карты;
    - прогресс игры.
5. Пользователь приступает к следующему вопросу.

**Альтернативный сценарий:**
- Если вопросы закончились:
    1. Система завершает игровой сеанс.
    2. Пользователь перенаправляется на экран итогов игры.

**Постусловия:**
- Следующий вопрос загружен  
    или
- Игра завершена.
## US-05. Досрочное завершение игры

**Описание:**  
**Как пользователь**, я хочу иметь возможность завершить игру до её окончания.

**Предусловия:**
- Игровая сессия активна.

**Основной сценарий:**
1. Пользователь нажимает кнопку **«Завершить игру»**.
2. Система запрашивает подтверждение действия.
3. Пользователь подтверждает завершение.
4. Система завершает текущую игровую сессию.
5. Система отображает итоговый результат на момент завершения.

**Альтернативный сценарий:**
- Если пользователь отменяет завершение:
    1. Система закрывает окно подтверждения.
    2. Пользователь продолжает игру с текущего вопроса.

**Постусловия:**
- Игровая сессия завершена.
- Итоговые данные отображены пользователю.
## US-06. Сохранение результата в рейтинге

**Описание:**  
**Как пользователь**, я хочу сохранить свой результат в таблице рейтинга после завершения игры.

**Предусловия:**
- Игровая сессия завершена.
- Результат текущей игры уже вычислен и хранится локально (например, в объекте сессии).

**Основной сценарий:**
1. После завершения игры система отображает итоговый результат.
2. Система предлагает ввести имя пользователя.
3. Пользователь вводит имя.
4. Пользователь подтверждает ввод.
5. Система предлагает сохранить результат в рейтинге.
6. Пользователь подтверждает сохранение результата.
7. Система отправляет данные на сервер.
8. Система сохраняет имя пользователя и количество набранных баллов.
9. Система отображает подтверждение успешного сохранения.

**Альтернативный сценарий:**
- Если пользователь оставил поле ввода пустым или отказался от сохранения:
	1. Кнопка "Сохранить результат" неактивна.
	2. Система не добавляет результат в рейтинг.
	3. Система позволяет выйти в главное меню.
    4. Пользователь может продолжить без сохранения.

**Постусловия:**
- Результат сохранён в таблице рейтинга  
    или
- Пользователь отказался от сохранения.
## US-07. Просмотр таблицы рейтинга

**Описание:**  
**Как пользователь**, я хочу видеть таблицу рейтинга и своё место в рейтинге для сравнения своего результата с результатами других игроков.

**Предусловия:**
- В системе есть сохранённые результаты игр.

**Основной сценарий:**
1. Пользователь открывает раздел **«Рейтинг»**.
2. Система загружает список лучших результатов.
3. Система отображает таблицу рейтинга.
4. Пользователь видит:
    - список игроков;
    - количество баллов;
    - своё место в рейтинге (если результат был сохранён).

**Альтернативный сценарий:**
- Если рейтинг пуст:
    1. Система отображает сообщение о том, что результатов пока нет.

**Постусловия:**
- Таблица рейтинга отображена пользователю.

# 1.2. Функциональные требования

## FR-01. Запуск викторины и выбор режима (US-01)

Обязательные:
- Система отображает стартовый экран при открытии приложения.
- Пользователь может выбрать режим игры перед началом (столицы, страны, достопримечательности).
- Система загружает первый вопрос после нажатия **«Начать игру»**.
- Создаётся игровая сессия пользователя.

Опциональные:
- Возможность выбора разных уровней сложности (легкий, средний, сложный).
- Возможность выбора количества вопросов за сессию.
## FR-02. Выбор ответа на карте (US-02)

Обязательные:
- Система отображает карту для каждого вопроса.
- Пользователь может кликать по карте для выбора ответа.
- Система отображает маркер в выбранной точке.
- Пользователь может изменить выбранную точку до подтверждения.
- Координаты ответа сохраняются после подтверждения.

## FR-03. Просмотр результата ответа (US-03)

Обязательные:
- Система принимает координаты ответа пользователя и вычисляет результат.
- Система определяет правильные координаты объекта.
- Система рассчитывает расстояние ошибки и количество баллов за ответ.
- Отображаются:
    - выбранная пользователем точка;
    - правильная точка;
    - расстояние ошибки;
    - начисленные баллы.
- Общий счёт пользователя обновляется.
- Система не позволяет завершить вопрос без выбора точки.

## FR-04. Переход к следующему вопросу (US-04)

Обязательные:
- Пользователь может перейти к следующему вопросу кнопкой **«Следующий вопрос»**.
- Новый вопрос загружается без перезагрузки страницы.
- Обновляются текст вопроса, состояние карты и прогресс игры.
- При окончании вопросов система завершает сессию и показывает итоговый экран.

## FR-05. Досрочное завершение игры (US-05)

Обязательные:
- Пользователь может завершить игру до окончания.
- Система запрашивает подтверждение при досрочном завершении.
- Если пользователь отменяет, игра продолжается с текущего вопроса.
- После подтверждения система завершает сессию и показывает итоговые данные.

## FR-06. Сохранение результата в рейтинге (US-06)

Обязательные:
- После окончания игры система отображает итоговый результат.
- Пользователь может ввести имя для сохранения результата.
- Кнопка сохранения неактивна, если имя пустое.
- Результат (имя + баллы) отправляется на сервер и сохраняется в рейтинге.

Опционально:
- Пользователь может отказаться от сохранения без потери локального результата.

## FR-07. Просмотр таблицы рейтинга (US-07)

- Система отображает таблицу рейтинга с именами игроков и количеством баллов.
- Пользователь видит актуальные данные и своё место в рейтинге (если результат сохранён).
- Если рейтинга нет, система показывает соответствующее сообщение.

# 1.3. Проектирование API

## Общие положения

Для взаимодействия клиентской части с сервером предполагается использование **REST API**.  
API предназначено для:
- запуска игровой сессии;
- получения вопросов;
- отправки ответов пользователя;
- перехода между вопросами;
- завершения игры;
- сохранения результата в рейтинг;
- просмотра таблицы рейтинга
### Формат обмена данными
- Формат запросов и ответов: **JSON**
- Базовый путь API: `/api`
## 1.3.1. Запуск новой игры

**Endpoint:** `POST /api/game/start`

**Назначение:**Создание новой игровой сессии и получение первого вопроса.

### Тело запроса

```json
{
  "mode": "capitals",
  "difficulty": "medium",
  "questionCount": 10
}
```

### Параметры запроса

|Поле|Тип|Обязательное|Описание|
|---|---|---|---|
|`mode`|string|да|Режим игры (`capitals`, `countries`, `landmarks`)|
|`difficulty`|string|нет|Уровень сложности (`easy`, `medium`, `hard`)|
|`questionCount`|number|нет|Количество вопросов в сессии|

### Успешный ответ

```json
{
  "sessionId": 101,
  "currentQuestion": {
    "questionId": 1,
    "text": "Отметьте на карте столицу Франции",
    "targetType": "city"
  },
  "progress": {
    "current": 1,
    "total": 10
  },
  "score": 0
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "INVALID_MODE",
  "message": "Указан недопустимый режим игры"
}
```

## 1.3.2. Получение текущего вопроса

**Endpoint:** `GET /api/game/{sessionId}/question`

**Назначение:** Получение текущего вопроса активной игровой сессии.
### Параметры пути

|Параметр|Тип|Описание|
|---|---|---|
|`sessionId`|number|Идентификатор игровой сессии|
### Успешный ответ

```json
{
  "questionId": 1,
  "text": "Отметьте на карте столицу Франции",
  "targetType": "city",
  "progress": {
    "current": 1,
    "total": 10
  }
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "SESSION_NOT_FOUND",
  "message": "Игровая сессия не найдена"
}
```

> Данный endpoint полезен для восстановления состояния игры, например после обновления страницы.

## 1.3.3. Отправка ответа на вопрос

**Endpoint:** `POST /api/game/{sessionId}/answer`

**Назначение:** Отправка координат, выбранных пользователем на карте, и вычисление результата ответа.

### Тело запроса

```json
{
  "questionId": 1,
  "selectedLat": 48.8566,
  "selectedLng": 2.3522
}
```

### Параметры запроса

|Поле|Тип|Обязательное|Описание|
|---|---|---|---|
|`questionId`|number|да|Идентификатор текущего вопроса|
|`selectedLat`|number|да|Широта выбранной точки|
|`selectedLng`|number|да|Долгота выбранной точки|

### Успешный ответ

```json
{
  "questionId": 1,
  "correctLat": 48.8566,
  "correctLng": 2.3522,
  "distanceKm": 12.4,
  "pointsEarned": 980,
  "totalScore": 980,
  "isLastQuestion": false
}
```

### Возможные ответы с ошибкой

```json
{
  "error": "ANSWER_ALREADY_SUBMITTED",
  "message": "Ответ на этот вопрос уже был отправлен"
}
```

```json
{
  "error": "INVALID_COORDINATES",
  "message": "Координаты ответа указаны некорректно"
}
```

## 1.3.4. Получение следующего вопроса

**Endpoint:** `GET /api/game/{sessionId}/next`

**Назначение:** Получение следующего вопроса после завершения текущего.
### Параметры пути

|Параметр|Тип|Описание|
|---|---|---|
|`sessionId`|number|Идентификатор игровой сессии|

### Успешный ответ (если вопросы ещё есть)

```json
{
  "questionId": 2,
  "text": "Отметьте на карте Бразилию",
  "targetType": "country",
  "progress": {
    "current": 2,
    "total": 10
  }
}
```

### Успешный ответ (если игра завершена)

```json
{
  "gameFinished": true,
  "finalScore": 7540
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "QUESTION_NOT_ANSWERED",
  "message": "Нельзя перейти к следующему вопросу до отправки ответа"
}
```

## 1.3.5. Досрочное завершение игры

**Endpoint:** `POST /api/game/{sessionId}/finish`

**Назначение:** Завершение игровой сессии до прохождения всех вопросов.

### Тело запроса

```json
{
  "reason": "user_exit"
}
```

### Успешный ответ

```json
{
  "sessionId": 101,
  "status": "finished",
  "answeredQuestions": 4,
  "totalQuestions": 10,
  "finalScore": 3150
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "SESSION_ALREADY_FINISHED",
  "message": "Игровая сессия уже завершена"
}
```

## 1.3.6. Получение итогов игры

**Endpoint:** `GET /api/game/{sessionId}/result`

**Назначение:** Получение итоговой информации по завершённой игровой сессии.

### Успешный ответ

```json
{
  "sessionId": 101,
  "mode": "capitals",
  "finalScore": 7540,
  "answeredQuestions": 10,
  "totalQuestions": 10,
  "finishedAt": "2026-04-05T14:10:00Z"
}
```

## 1.3.7. Сохранение результата в рейтинг

**Endpoint:** `POST /api/leaderboard`

**Назначение:** Сохранение итогового результата завершённой игры в таблице рейтинга.

### Тело запроса

```json
{
  "sessionId": 101,
  "playerName": "Mika"
}
```

### Параметры запроса

|Поле|Тип|Обязательное|Описание|
|---|---|---|---|
|`sessionId`|number|да|Идентификатор завершённой игровой сессии|
|`playerName`|string|да|Имя игрока для отображения в рейтинге|

### Успешный ответ

```json
{
  "message": "Результат успешно сохранён",
  "leaderboardEntryId": 55,
  "rank": 7
}
```

### Возможные ответы с ошибкой

```json
{
  "error": "EMPTY_PLAYER_NAME",
  "message": "Имя игрока не может быть пустым"
}
```

```json
{
  "error": "SESSION_NOT_FINISHED",
  "message": "Нельзя сохранить незавершённую игру"
}
```
## 1.3.8. Получение таблицы рейтинга

**Endpoint:** `GET /api/leaderboard`

**Назначение:** Получение списка лучших результатов игроков.

### Query-параметры

|Параметр|Тип|Обязательное|Описание|
|---|---|---|---|
|`limit`|number|нет|Количество записей для отображения|
|`mode`|string|нет|Фильтр по режиму игры|

### Пример запроса

```http
GET /api/leaderboard?limit=10&mode=capitals
```

### Успешный ответ

```json
{
  "items": [
    {
      "rank": 1,
      "playerName": "Alex",
      "score": 9850,
      "mode": "capitals",
      "playedAt": "2026-04-05T13:00:00Z"
    },
    {
      "rank": 2,
      "playerName": "Mika",
      "score": 7540,
      "mode": "capitals",
      "playedAt": "2026-04-05T14:10:00Z"
    }
  ]
}
```

### Ответ при пустом рейтинге

```json
{
  "items": []
}
```

# 1.4. Модель данных

Для реализации серверной части системы предлагается использовать следующие основные сущности:

- **Question** — вопрос викторины;
- **GameSession** — игровая сессия пользователя;
- **Answer** — ответ пользователя на вопрос;
- **LeaderboardEntry** — запись в таблице рейтинга.

## 1.4.1. Сущность Question

**Назначение:** Сущность хранит данные о географическом объекте, который используется в качестве вопроса викторины.

### Поля

| Поле           | Тип     | Описание                                          |
| -------------- | ------- | ------------------------------------------------- |
| `id`           | number  | Уникальный идентификатор вопроса                  |
| `questionText` | string  | Текст вопроса                                     |
| `mode`         | string  | Режим игры (`capitals`, `countries`, `landmarks`) |
| `targetName`   | string  | Название объекта                                  |
| `targetType`   | string  | Тип объекта (`city`, `country`, `landmark`)       |
| `correctLat`   | float   | Правильная широта                                 |
| `correctLng`   | float   | Правильная долгота                                |

## Связи между сущностями

Между сущностями предполагаются следующие связи:
- **GameSession → Answer** — связь **один ко многим**  
    Одна игровая сессия может содержать несколько ответов пользователя.
- **Question → Answer** — связь **один ко многим**  
    Один и тот же вопрос может использоваться в разных игровых сессиях.
- **GameSession → LeaderboardEntry** — связь **один к нулю или одному**  
    Одна игровая сессия может быть сохранена в рейтинге один раз либо не быть сохранена вовсе.
- **AdminUser → Question** — связь **один ко многим**  
    Админ может создавать или редактировать множество вопросов, каждый вопрос связан с администратором, который его добавил.

## Логическая структура базы данных

Для хранения данных предполагается использование следующих таблиц:
- `questions` — вопросы викторины
- `game_sessions` — сессии игроков
- `answers` — ответы пользователей
- `leaderboard` — итоговые результаты
- `admin_users` — данные администраторов

## Ограничения данных

Для обеспечения корректности данных рекомендуется ввести следующие ограничения:
- `playerName` не должен быть пустым;
- `score` не может быть отрицательным;
- `selectedLat` должен находиться в диапазоне **[-90; 90]**;
- `selectedLng` должен находиться в диапазоне **[-180; 180]**;
- `correctLat` должен находиться в диапазоне **[-90; 90]**;
- `correctLng` должен находиться в диапазоне **[-180; 180]**;
- результат может быть сохранён в рейтинг **только после завершения игровой сессии**;
- в рамках одной игровой сессии один и тот же вопрос не должен быть отвечен более одного раза.
- Для админки:
	- - `username` уникален
	- `email` уникален (если указан)
	- Пароль хранится только в виде хэша
	- `isActive = false` блокирует доступ к админке

# 1.5. Ключевые технические решения

## 1.5.1. Frontend:

**Тип:** веб-приложение

**Технологии:** React, TypeScript, CSS Modules

**Причины выбора:**
- Легко интегрируется с REST API FastAPI
- Позволяет быстро реализовать интерфейс викторины, карты, прогресса игры и таблицы рейтинга
- Кроссплатформенность: работает в любом современном браузере
- Компонентная архитектура упрощает добавление новых элементов и анимаций

## 1.5.2. Backend

**Тип:** REST API

**Технологии:** Python (FastAPI)

**Причины выбора:**
- Простая и быстрая реализация API для работы с вопросами, ответами и игровыми сессиями
- Поддержка JSON и валидации данных по умолчанию
- Лёгкий запуск и отладка на локальной машине
- Можно быстро интегрировать дополнительную логику, например расчёт очков и рейтинг

## 1.5.3. База данных

**Тип:** PostgreSQL (облачное размещение через Supabase)

**Причины выбора:**
- Надёжное хранение структурированных данных
- Поддержка связей между сущностями: вопросы, ответы, сессии, рейтинг
- Подходит для локальной разработки и деплоя
- Простое резервное копирование и дальнейшее расширение проекта

## 1.5.4. ORM

**Технологии:** SQLAlchemy

**Причины выбора:**
- Упрощает работу с таблицами и связями
- Снижает количество ручного SQL-кода
- Улучшает читаемость и поддержку backend-кода
- Удобно интегрируется с PostgreSQL

## 1.5.5. Кэширование (опционально)

**Технологии:** Redis

**Причины выбора:**
- Хранение временных игровых данных
- Кэширование часто запрашиваемой информации
- Ускорение доступа к таблице лидеров
- Используется только для оптимизации, не является обязательным

## 1.5.6. Безопасность

**Меры:**
- Валидация входных данных
- Проверка допустимых координат
- Защита от некорректных запросов
- Использование ORM для снижения риска SQL Injection

## 1.5.7. Контейнеризация

**Технологии:** Docker, Docker Compose

**Причины выбора:**
- Единая среда запуска на Windows и Linux
- Упрощение настройки проекта и запуск всех сервисов одновременно
- Лёгкая демонстрация проекта

## 1.5.8. Деплой (опционально)

**Варианты:**
- **Frontend** — Vercel
- **Backend** — Render / Railway
- **База данных** — PostgreSQL (Supabase)

**Причины выбора:**
- Простота настройки
- Наличие бесплатных или условно-бесплатных тарифов
- Возможность проверить работу проекта вне локальной среды
- Удобство публикации и демонстрации итогового результата

# 1.1. Пользовательские сценарии
## US-01. Запуск викторины и выбор режима

**Описание:**
**Как пользователь**, я хочу запустить викторину и выбрать режим.

**Предусловия:**
- Пользователь открыл веб-приложение.
- Главная страница успешно загружена.

**Основной сценарий:**
1. Пользователь открывает приложение.
2. Система отображает стартовый экран.
3. Пользователь выбирает режим игры.
4. Пользователь нажимает кнопку **«Продолжить»**.
5. Система перенаправляет на экран выбора сложности.
6. Пользователь выбирает сложность.
7. Пользователь нажимает кнопку **«Начать игру»**.
8. Система создаёт игровую сессию и загружает первый вопрос.
9. Пользователь переходит на экран викторины.

**Постусловия:**
- Игровая сессия создана.
- Пользователь находится на первом вопросе викторины.

## US-02. Выбор ответа на карте

**Описание:**
**Как пользователь**, я хочу отметить место на карте, чтобы ответить на вопрос.

**Предусловия:**
- Игра запущена.
- Текущий вопрос загружен.
- Карта отображается корректно.

**Основной сценарий:**
1. Система отображает текст вопроса.
2. Пользователь изучает карту.
3. Пользователь кликает по предполагаемому месту на карте.
4. Система отображает маркер в выбранной точке.
5. Пользователь может изменить ответ, кликнув в другом месте (до подтверждения).
6. Пользователь нажимает кнопку **«Ответить»**.
7. Система отправляет координаты ответа на сервер.
8. Система получает результат (расстояние, баллы).

**Альтернативный сценарий:**
- Если пользователь не выбрал точку:
    1. Кнопка **«Ответить»** неактивна.
    2. Система не позволяет отправить ответ.

**Постусловия:**
- Координаты ответа пользователя зафиксированы.
- Результат ответа отображён.

## US-03. Просмотр результата ответа

**Описание:**
**Как пользователь**, я хочу получить результат ответа, чтобы понять, насколько точно я отметил местоположение объекта.

**Предусловия:**
- Пользователь отправил ответ.
- Сервер вернул оценку.

**Основной сценарий:**
1. Система принимает результат от сервера.
2. Система отображает:
   - выбранную пользователем точку;
   - правильную точку;
   - расстояние ошибки;
   - количество начисленных баллов.
3. Общий счёт пользователя обновляется.
4. Появляется кнопка **«Далее»** для перехода к следующему вопросу.

**Постусловия:**
- Ответ пользователя оценён.
- Баллы начислены.
- Результат текущего вопроса отображён.

## US-04. Переход к следующему вопросу

**Описание:**
**Как пользователь**, я хочу быстро переходить к следующему вопросу.

**Предусловия:**
- Результат текущего вопроса уже показан.

**Основной сценарий:**
1. Пользователь нажимает кнопку **«Далее»**.
2. Система запрашивает следующий вопрос у сервера.
3. Новый вопрос подгружается без перезагрузки страницы.
4. Система обновляет:
   - текст вопроса;
   - состояние карты;
   - прогресс игры.
5. Пользователь приступает к следующему вопросу.

**Альтернативный сценарий:**
- Если вопросы закончились:
    1. Система завершает игровой сеанс.
    2. Пользователь перенаправляется на экран итогов игры.

**Постусловия:**
- Следующий вопрос загружен
  или
- Игра завершена.

## US-05. Досрочное завершение игры

**Описание:**
**Как пользователь**, я хочу иметь возможность завершить игру до её окончания.

**Предусловия:**
- Игровая сессия активна.

**Основной сценарий:**
1. Пользователь может выйти из игры в любой момент (напр., через кнопку "Выход").
2. Система завершает текущую игровую сессию.
3. Система отображает итоговый результат на момент завершения.

**Постусловия:**
- Игровая сессия завершена.
- Итоговые данные отображены пользователю.

## US-06. Сохранение результата в рейтинге

**Описание:**
**Как пользователь**, я хочу сохранить свой результат в таблице рейтинга после завершения игры.

**Предусловия:**
- Игровая сессия завершена.
- Результат текущей игры отображён.

**Основной сценарий:**
1. После завершения игры система отображает итоговый результат.
2. Система предлагает ввести имя пользователя.
3. Пользователь вводит имя.
4. Пользователь нажимает кнопку **«Сохранить результат»**.
5. Система отправляет данные на сервер.
6. Система сохраняет имя пользователя и количество набранных баллов.
7. Система отображает подтверждение успешного сохранения.
8. Система загружает обновлённую таблицу рейтинга с указанием позиции пользователя.

**Альтернативный сценарий:**
- Если пользователь оставил поле ввода пустым:
  1. Кнопка **«Сохранить результат»** неактивна.
  2. Система не добавляет результат в рейтинг.
  3. Пользователь может выйти в главное меню.

**Постусловия:**
- Результат сохранён в таблице рейтинга
  или
- Пользователь отказался от сохранения.

## US-07. Просмотр таблицы рейтинга

**Описание:**
**Как пользователь**, я хочу видеть таблицу рейтинга и своё место в рейтинге для сравнения своего результата с результатами других игроков.

**Предусловия:**
- В системе есть сохранённые результаты игр.

**Основной сценарий:**
1. Пользователь открывает раздел **«Рейтинг»**.
2. Система загружает список лучших результатов для каждого режима.
3. Система отображает таблицу рейтинга с вкладками по режимам.
4. Пользователь видит:
   - список игроков;
   - количество баллов;
   - дату игры.
5. Пользователь может переключаться между режимами.

**Альтернативный сценарий:**
- Если рейтинг пуст:
  1. Система отображает сообщение о том, что результатов пока нет.

**Постусловия:**
- Таблица рейтинга отображена пользователю.

## US-08. Администрирование вопросов

**Описание:**
**Как администратор**, я хочу управлять вопросами викторины (добавлять, редактировать, удалять, отключать).

**Предусловия:**
- Администратор авторизован в системе.

**Основной сценарий:**
1. Администратор переходит в админ-панель.
2. Система отображает список всех вопросов.
3. Администратор может:
   - Добавить новый вопрос (заполнить форму).
   - Редактировать существующий вопрос.
   - Удалить вопрос.
   - Включить/отключить вопрос (через переключатель `is_active`).
4. Изменения сохраняются в базе данных.

**Постусловия:**
- Вопросы обновлены в системе.

# 1.2. Функциональные требования

## FR-01. Запуск викторины и выбор режима (US-01)

Обязательные:
- Система отображает стартовый экран при открытии приложения.
- Пользователь может выбрать режим игры перед началом (столицы, страны, достопримечательности).
- Пользователь может выбрать уровень сложности (лёгкий, средний, сложный).
- Количество вопросов по умолчанию: 5 (настраивается в коде).
- Система создаёт игровую сессию и загружает первый вопрос после нажатия **«Начать игру»**.

## FR-02. Выбор ответа на карте (US-02)

Обязательные:
- Система отображает интерактивную карту (Leaflet) для каждого вопроса.
- Пользователь может кликать по карте для выбора ответа.
- Система отображает маркер в выбранной точке.
- Пользователь может изменить выбранную точку до подтверждения.
- Координаты ответа отправляются на сервер после нажатия **«Ответить»**.

## FR-03. Просмотр результата ответа (US-03)

Обязательные:
- Система получает от сервера: расстояние ошибки, начисленные баллы.
- Отображаются:
   - выбранная пользователем точка;
   - правильная точка;
   - расстояние ошибки (в км);
   - начисленные баллы.
- Общий счёт пользователя обновляется.

## FR-04. Переход к следующему вопросу (US-04)

Обязательные:
- Пользователь может перейти к следующему вопросу кнопкой **«Далее»**.
- Новый вопрос загружается без перезагрузки страницы.
- Обновляются текст вопроса, состояние карты и прогресс игры.
- При окончании вопросов система завершает сессию и показывает итоговый экран.

## FR-05. Досрочное завершение игры (US-05)

Обязательные:
- Пользователь может завершить игру до окончания.
- После завершения система показывает итоговые данные.

## FR-06. Сохранение результата в рейтинге (US-06)

Обязательные:
- После окончания игры система отображает итоговый результат.
- Пользователь может ввести имя для сохранения результата (2–50 символов).
- Кнопка сохранения неактивна, если имя пустое.
- Результат (имя + баллы + режим) отправляется на сервер и сохраняется в рейтинге.

## FR-07. Просмотр таблицы рейтинга (US-07)

- Система отображает таблицу рейтинга с именами игроков, количеством баллов и датой игры.
- Пользователь видит актуальные данные.
- Таблица разделена по режимам (вкладки).
- Если рейтинга нет, система показывает соответствующее сообщение.

## FR-08. Администрирование вопросов (US-08)

- Администратор может авторизоваться через `/admin/login`.
- Администратор может просматривать все вопросы.
- Администратор может создавать новые вопросы с полями:
  - `question_text` — текст вопроса
  - `mode` — режим (`capitals`, `countries`, `landmarks`)
  - `target_name` — название объекта
  - `target_type` — тип (`country`, `capital`, `landmark`)
  - `correct_lat`, `correct_lng` — координаты
  - `difficulty` — уровень сложности
  - `is_active` — активен ли вопрос
- Администратор может редактировать и удалять вопросы.
- Администратор может переключать `is_active` для скрытия вопроса.

# 1.3. Проектирование API

## Общие положения

Для взаимодействия клиентской части с сервером используется **REST API**.
API предназначено для:
- запуска игровой сессии;
- получения вопросов;
- отправки ответов пользователя;
- перехода между вопросами;
- завершения игры;
- сохранения результата в рейтинг;
- просмотра таблицы рейтинга;
- управления вопросами (админка).

### Формат обмена данными
- Формат запросов и ответов: **JSON**
- Базовый путь API: `/api`
- Все поля в запросах и ответах используют **snake_case** (Python-стиль).

## 1.3.1. Запуск новой игры

**Endpoint:** `POST /api/game/start`

**Назначение:** Создание новой игровой сессии и получение первого вопроса.

### Тело запроса

```json
{
  "mode": "capitals",
  "difficulty": "medium",
  "question_count": 5
}
```

### Параметры запроса

| Поле | Тип | Обязательное | Описание |
|------|----|--------------|----------|
| `mode` | string | да | Режим игры (`capitals`, `countries`, `landmarks`) |
| `difficulty` | string | нет | Уровень сложности (`easy`, `medium`, `hard`), по умолчанию `medium` |
| `question_count` | number | нет | Количество вопросов в сессии (1–20), по умолчанию 5 |

### Успешный ответ

```json
{
  "session_id": 101,
  "question": {
    "question_id": 1,
    "text": "Отметьте на карте столицу Франции",
    "target_type": "city",
    "target_name": "Paris",
    "correct_country_code": "FR"
  },
  "progress": {
    "current": 1,
    "total": 5
  },
  "score": 0
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "INVALID_MODE",
  "message": "Указан недопустимый режим игры"
}
```

## 1.3.2. Получение текущего вопроса

**Endpoint:** `GET /api/game/{session_id}/question`

**Назначение:** Получение текущего вопроса активной игровой сессии.

### Параметры пути

| Параметр | Тип | Описание |
|----------|----|----------|
| `session_id` | number | Идентификатор игровой сессии |

### Успешный ответ

```json
{
  "question_id": 1,
  "text": "Отметьте на карте столицу Франции",
  "target_type": "city",
  "target_name": "Paris",
  "correct_country_code": "FR",
  "progress": {
    "current": 1,
    "total": 5
  }
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "SESSION_NOT_FOUND",
  "message": "Игровая сессия не найдена"
}
```

## 1.3.3. Отправка ответа на вопрос

**Endpoint:** `POST /api/game/{session_id}/answer`

**Назначение:** Отправка координат, выбранных пользователем на карте, и вычисление результата ответа.

### Тело запроса

```json
{
  "question_id": 1,
  "selected_lat": 48.8566,
  "selected_lng": 2.3522
}
```

### Параметры запроса

| Поле | Тип | Обязательное | Описание |
|------|----|--------------|----------|
| `question_id` | number | да | Идентификатор текущего вопроса |
| `selected_lat` | number | да | Широта выбранной точки (диапазон: -90..90) |
| `selected_lng` | number | да | Долгота выбранной точки (диапазон: -180..180) |

### Успешный ответ

```json
{
  "question_id": 1,
  "correct_lat": 48.8566,
  "correct_lng": 2.3522,
  "distance_km": 12.4,
  "points_earned": 980,
  "total_score": 980,
  "is_last_question": false
}
```

### Возможные ответы с ошибкой

```json
{
  "error": "ANSWER_ALREADY_SUBMITTED",
  "message": "Ответ на этот вопрос уже был отправлен"
}
```

```json
{
  "error": "INVALID_COORDINATES",
  "message": "Координаты ответа указаны некорректно"
}
```

## 1.3.4. Получение следующего вопроса

**Endpoint:** `GET /api/game/{session_id}/next`

**Назначение:** Получение следующего вопроса после завершения текущего.

### Параметры пути

| Параметр | Тип | Описание |
|----------|----|----------|
| `session_id` | number | Идентификатор игровой сессии |

### Успешный ответ (если вопросы ещё есть)

```json
{
  "question": {
    "question_id": 2,
    "text": "Отметьте на карте Бразилию",
    "target_type": "country",
    "target_name": "Brazil",
    "correct_country_code": "BR"
  },
  "progress": {
    "current": 2,
    "total": 5
  },
  "score": 980
}
```

### Успешный ответ (если игра завершена)

```json
{
  "game_finished": true,
  "final_score": 7540
}
```

### Возможный ответ с ошибкой

```json
{
  "error": "QUESTION_NOT_ANSWERED",
  "message": "Нельзя перейти к следующему вопросу до отправки ответа"
}
```

**Назначение:** Завершение игровой сессии до прохождения всех вопросов.

```json
{
```

```json
  "final_score": 3150
}
```

```json
{
  "error": "SESSION_ALREADY_FINISHED",

}
```

```json
}
```

## 1.3.7. Сохранение результата в рейтинг

**Endpoint:** `POST /api/leaderboard/save`

**Назначение:** Сохранение итогового результата завершённой игры в таблице рейтинга.

### Тело запроса

```json
{
  "session_id": 101,
  "player_name": "Mika"
}
```

### Параметры запроса

| Поле | Тип | Обязательное | Описание |
|------|----|--------------|----------|
| `session_id` | number | да | Идентификатор завершённой игровой сессии |
| `player_name` | string | да | Имя игрока (2–50 символов) |

### Успешный ответ

```json
{
  "message": "Результат успешно сохранён",
  "leaderboard_entry_id": 55,
  "rank": 7
}
```

### Возможные ответы с ошибкой

```json
{
  "error": "EMPTY_PLAYER_NAME",
  "message": "Имя игрока не может быть пустым"
}
```

```json
{
  "error": "SESSION_NOT_FINISHED",
  "message": "Нельзя сохранить незавершённую игру"
}
```

## 1.3.8. Получение таблицы рейтинга

**Endpoint:** `GET /api/leaderboard`

**Назначение:** Получение списка лучших результатов игроков для указанного режима.

### Query-параметры

| Параметр | Тип | Обязательное | Описание |
|----------|----|--------------|----------|
| `mode` | string | да | Режим игры (`capitals`, `countries`, `landmarks`) |

### Пример запроса

```http
GET /api/leaderboard?mode=capitals
```

### Успешный ответ

```json
{
  "items": [
    {
      "rank": 1,
      "player_name": "Alex",
      "score": 9850,
      "mode": "capitals",
      "played_at": "2026-04-19T08:30:00Z"
    },
    {
      "rank": 2,
      "player_name": "Mika",
      "score": 7540,
      "mode": "capitals",
      "played_at": "2026-04-19T08:15:00Z"
    }
  ]
```

# 1.4. Модель данных

Для реализации серверной части системы используются следующие основные сущности:

- **Question** — вопрос викторины;
- **GameSession** — игровая сессия пользователя;
- **Answer** — ответ пользователя на вопрос;
- **LeaderboardEntry** — запись в таблице рейтинга;
- **SessionQuestion** — связь сессии с вопросами;
- **AdminUser** — администратор системы.

## 1.4.1. Сущность Question

**Назначение:** Сущность хранит данные о географическом объекте, который используется в качестве вопроса викторины.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор вопроса |
| `question_text` | string | Текст вопроса |
| `mode` | string | Режим игры (`capitals`, `countries`, `landmarks`) |
| `target_name` | string | Название объекта |
| `target_type` | string | Тип объекта (`country`, `capital`, `landmark`) |
| `correct_lat` | float | Правильная широта |
| `correct_lng` | float | Правильная долгота |
| `correct_country_code` | string / null | ISO код страны (опционально, для режима countries) |
| `difficulty` | string | Уровень сложности (`easy`, `medium`, `hard`) |
| `is_active` | boolean | Признак доступности вопроса |

### Пример

```json
{
  "id": 1,
  "question_text": "Отметьте на карте столицу Франции",
  "mode": "capitals",
  "target_name": "Paris",
  "target_type": "city",
  "correct_lat": 48.8566,
  "correct_lng": 2.3522,
  "correct_country_code": "FR",
  "difficulty": "medium",
  "is_active": true
}
```

## 1.4.2. Сущность GameSession

**Назначение:** Сущность хранит информацию о текущей или завершённой игровой сессии пользователя.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор сессии |
| `mode` | string | Выбранный режим игры |
| `difficulty` | string | Уровень сложности |
| `total_questions` | number | Общее количество вопросов |
| `score` | number | Текущий суммарный счёт |
| `status` | string | Статус сессии (`active`, `finished`) |
| `started_at` | datetime | Время начала игры |
| `finished_at` | datetime / null | Время завершения игры |
| `player_name` | string / null | Имя игрока (если сохранил результат) |

### Пример

```json
{
  "id": 101,
  "mode": "capitals",
  "difficulty": "medium",
  "total_questions": 5,
  "score": 3150,
  "status": "active",
  "started_at": "2026-04-19T08:00:00Z",
  "finished_at": null,
  "player_name": null
}
```

## 1.4.3. Сущность Answer

**Назначение:** Сущность хранит ответ пользователя на конкретный вопрос в рамках игровой сессии.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор ответа |
| `session_id` | number | Идентификатор игровой сессии |
| `question_id` | number | Идентификатор вопроса |
| `selected_lat` | number | Выбранная пользователем широта |
| `selected_lng` | number | Выбранная пользователем долгота |
| `distance_km` | number | Ошибка в километрах |
| `points_earned` | number | Начисленные баллы |
| `answered_at` | datetime | Время отправки ответа |

### Пример

```json
{
  "id": 501,
  "session_id": 101,
  "question_id": 1,
  "selected_lat": 48.90,
  "selected_lng": 2.40,
  "distance_km": 12.4,
  "points_earned": 980,
  "answered_at": "2026-04-19T08:05:00Z"
}
```

## 1.4.4. Сущность LeaderboardEntry

**Назначение:** Сущность хранит итоговый результат игрока, сохранённый в рейтинге.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор записи |
| `session_id` | number | Идентификатор завершённой игровой сессии |
| `player_name` | string | Имя игрока |
| `score` | number | Итоговый счёт |
| `mode` | string | Режим игры |
| `played_at` | datetime | Время завершения игры |

### Пример

```json
{
  "id": 55,
  "session_id": 101,
  "player_name": "Mika",
  "score": 7540,
  "mode": "capitals",
  "played_at": "2026-04-19T08:30:00Z"
}
```

## 1.4.5. Сущность SessionQuestion

**Назначение:** Сущность связывает игровую сессию с вопросами, определяя порядок вопросов в рамках одной сессии.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор |
| `session_id` | number | Идентификатор игровой сессии |
| `question_id` | number | Идентификатор вопроса |
| `order_index` | number | Порядок вопроса в сессии |

### Ограничения
- Уникальная пара `session_id` + `order_index`

### Пример

```json
{
  "id": 1,
  "session_id": 101,
  "question_id": 1,
  "order_index": 0
}
```

## 1.4.6. Сущность AdminUser

**Назначение:** Сущность хранит данные администратора, который может добавлять/редактировать/удалять вопросы.

### Поля

| Поле | Тип | Описание |
|------|----|----------|
| `id` | number | Уникальный идентификатор |
| `username` | string | Логин администратора (уникальный) |
| `password` | string | Хэш пароля |
| `email` | string | Контактный email (уникальный) |
| `is_active` | boolean | Аккаунт активен или нет |

### Ограничения
- `username` уникален
- `email` уникален
- Пароль хранится только в виде хэша

### Пример

```json
{
  "id": 1,
  "username": "admin",
  "password": "$2b$12$...",
  "email": "admin@example.com",
  "is_active": true
}
```

## Связи между сущностями

- **GameSession → Answer** — связь **один ко многим**
- **Question → Answer** — связь **один ко многим**
- **GameSession → LeaderboardEntry** — связь **один к нулю или одному**
- **GameSession → SessionQuestion** — связь **один ко многим**
- **Question → SessionQuestion** — связь **один ко многим**
- **AdminUser → Question** — связь **один ко многим**

## Логическая структура базы данных

Таблицы:
- `questions` — вопросы викторины
- `game_sessions` — сессии игроков
- `answers` — ответы пользователей
- `leaderboard` — итоговые результаты
- `session_questions` — порядок вопросов в сессиях
- `admin_users` — данные администраторов

## Ограничения данных

- `player_name` не должен быть пустым (мин. 2 символа);
- `score` не может быть отрицательным;
- `selected_lat` ∈ [-90; 90];
- `selected_lng` ∈ [-180; 180];
- `correct_lat` ∈ [-90; 90];
- `correct_lng` ∈ [-180; 180];
- результат может быть сохранён в рейтинг **только после завершения игровой сессии**;
- в рамках одной игровой сессии один и тот же вопрос не должен быть отвечен более одного раза;
- в рамках одной сессии порядок вопросов уникален (`order_index` уникален для `session_id`);
- один и тот же вопрос не может быть назначен в одну сессию более одного раза;
- для админки:
  - `username` уникален;
  - `email` уникален;
  - пароль хранится только в виде хэша;
  - `is_active = false` блокирует доступ.

# 1.5. Ключевые технические решения

## 1.5.1. Frontend

**Тип:** веб-приложение

**Технологии:** React, Vite, Leaflet (react-leaflet), Zustand, CSS Modules

**Причины выбора:**
- Vite обеспечивает быструю сборку и горячую перезагрузку
- Leaflet — лёгкая и мощная библиотека для работы с картами
- react-leaflet предоставляет React-компоненты для удобной интеграции
- Zustand — простое и эффективное состояние глобального хранилища
- CSS Modules позволяют изолировать стили компонентов

## 1.5.2. Backend

**Тип:** REST API

**Технологии:** Python (FastAPI), SQLAlchemy, Alembic

**Причины выбора:**
- Простая и быстрая реализация API для работы с вопросами, ответами и игровыми сессиями
- Поддержка JSON и валидации данных по умолчанию (Pydantic)
- Лёгкий запуск и отладка на локальной машине
- Alembic для миграций базы данных
- SQLAlchemy для ORM

## 1.5.3. База данных

**Тип:** PostgreSQL

**Причины выбора:**
- Надёжное хранение структурированных данных
- Поддержка связей между сущностями: вопросы, ответы, сессии, рейтинг
- Локальная разработка через Docker Compose
- Возможность использования Supabase для облачного хостинга

## 1.5.4. Контейнеризация

**Технологии:** Docker, Docker Compose

**Причины выбора:**
- Единая среда запуска на Windows и Linux
- Упрощение настройки проекта и запуск всех сервисов одновременно
- Лёгкая демонстрация проекта

## 1.5.5. Деплой (опционально)

**Варианты:**
- **Frontend** — Vercel / Netlify
- **Backend** — Render / Railway
- **База данных** — PostgreSQL (Supabase)

**Причины выбора:**
- Простота настройки
- Наличие бесплатных или условно-бесплатных тарифов
- Возможность проверить работу проекта вне локальной среды
- Удобство публикации и демонстрации итогового результата
